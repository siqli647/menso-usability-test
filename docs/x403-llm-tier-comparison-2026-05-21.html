Excluded / Harness-Only Attempts

These were intentionally kept out of the 5-product comparison because they did not produce clean, publishable product evidence.

  • Tally: Code-based email verification handoff could be accepted while the browser runner timed out filling the code. The verification URL worked when checked directly, so this is an auth-handoff stability issue rather than product evidence.
  • Whale Starts: Cheap_real used mina.walker@example.com and fake codes, then queue cleanliness marked the run clean. Artifacts were removed and a placeholder-input cleanliness gate was added.
  • BetaList: Signup hit reCAPTCHA and then a sign-in/signup loop, so it was excluded from the cost-tier comparison set.
  • Small Bets / Gumroad: Gumroad disables rrweb and checkout navigation returned net::ERR_ABORTED. The run was stopped because it could not satisfy the replay requirement.
  • LeadGravity 12-step retry: The fresh cheap_real retry was discarded by cleanliness because the report contained low-confidence/polluted insight text. The older 30-step cheap run was not used because it was not comparable with the 12-step local-saving tier.
  • Schole AI: Clicking the demo CTA crashed the browser page and the run correctly persisted as harness_failed, not as a product result.

Operating Guidance

Use standard for final sales/customer-facing reports, account-gated workflows, and anything where product judgment depends on navigating setup, forms, or verification.

Use cheap_real as a first-pass triage route for public landing pages, directories, pricing pages, and obvious access blockers. Require deterministic cleanup gates and do not count runs with placeholder inputs, rrweb-disabled hosts, browser crashes, or failed verification handoff.
