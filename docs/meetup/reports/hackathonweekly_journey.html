UX/UI Frictions

1. As a fast-scanning student builder, Yuki expects a visible path from an interesting event to a low-commitment join…
On the event detail page, replace the disabled registration control with an active button that opens the auth options directly, and add a short inline note under it explaining that login is required to register.
2. Yuki came to evaluate one community workflow, not commit to a full membership account.
On the signup page, offer a lighter-weight event RSVP path for first-time visitors, such as email-only registration or a guest hold, before requiring full profile creation.
3. Yuki actively checks dates and participation details to judge whether an opportunity is real and current.
On the event detail page, show an explicit status next to capacity, such as "30 spots • Full" or "Waitlist open," so visitors can immediately understand whether they can still participate.
4. The brand promise suggests an active hackathon community, so Yuki expects to find something current or upcoming…
On the events page, surface the next upcoming activity above empty-state messaging so first-time visitors immediately see that the community still has future opportunities.
