03 · Journey findings

The main workflow is not the problem

The opportunity is to protect first-use continuity at the upload requirement and the credit boundary.

Strength

Observed: Jordan selected an app, uploaded the supplied image, chose quantity, style, and size, then reached Review without navigation recovery.

Keep: The guided sequence, visible upload thumbnail, and focused Review step.

P1 · First value

Payment pressure arrives before proof

Observed: The account had zero credits and Review stated that the selected size used one credit. Jordan stopped rather than crossing an unavailable paid boundary.

“That's my stopping point — I'm not clicking Review copy since that would burn a credit I don't have.”

Recommendation: Let a new user see one complete result, or a faithful watermarked preview, before asking for a credit decision.

P2 · Guardrail

Skipping upload can silently discard setup

Observed: In an earlier same-day pass, configuration did not persist when the screenshot step was skipped. The successful pass worked once the required image was uploaded.

Implication: A first-time user can interpret the reset as product failure instead of a missing prerequisite.

Recommendation: Block continuation with a specific upload-required message and retain already-entered configuration.
